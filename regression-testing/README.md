# 多案例回归测试与成本分析

这不是线上生产链路，也不是每次生成图片都必须执行的步骤。只有文本流水线或相关公共代码发生修改时，才使用 10 篇固定案例对受影响的阶段做逐阶段回归，记录结构验收、质量评分、请求数、Token、缓存、耗时和估算费用。

单阶段规则修改运行“问题案例 + 3 篇哨兵案例”；如果修改影响公共 Schema、模型适配器、checkpoint、跨阶段字段或公共校验器，则运行受影响阶段的全部 10 篇案例。生图流水线可以直接消费文本流水线验收通过的结果，但不属于这套文本阶段回归测试的下游必经步骤。

## 测试方式

- 真实模型适配器：验证实际 API 行为；
- 回放适配器：复用已保存响应，不产生新的模型费用；
- 代码验收：检查编号、覆盖、Schema、参考图和比例；
- 人工抽查：阅读问题案例和哨兵案例，避免把“命令成功”误判为质量通过；
- 稳定基线：只有全量通过、路径和哈希可追溯、质量与成本对比完成后才冻结。
